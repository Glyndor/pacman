# suite-scope.txt -- which paths can change each suite's verdict.
#
# A pull request that touches none of the paths listed for a suite cannot change
# what that suite concludes, so the suite does not have to run to learn what it
# already knows. The decision is made by scripts/quality/scope/ci-job-scope.sh, in
# its `suites` mode, and the job and its required checks `shell / test` and
# `gate` report exactly as before.
#
# WHY IT IS SAFE
#
#   * It fails open, in every direction. A suite with no entry here always runs. A
#     suite whose entry has no pattern is refused. A diff that cannot be read, a
#     rename, a copy, a type change, a push, a schedule or a workflow dispatch runs
#     every suite. A wrong skip lets a change merge untested; a wrong run costs
#     seconds, and the asymmetry decides every borderline case in favour of running.
#
#   * The decision is taken with the resolver and this map as they are in the BASE
#     commit, not as the pull request ships them, so a pull request that rewrites the
#     map or the resolver to narrow its own scope gets the full set instead.
#
#   * The map, the resolver and the runner are an input of every suite. The rule is in
#     ci-job-scope.sh and not in an entry per suite, so a suite added below later
#     cannot forget it.
#
#   * The names of the suites here are the paths tests.yml passes to
#     tests/ci/suites/check-suite-completeness.test.sh, so the workflow still names
#     every suite and tests/ci/suites/ci-runs-every-test.test.sh still sees a
#     complete list. Only the decision to EXECUTE a suite changes.
#
# HOW THE ENTRIES WERE DERIVED
#
# Each suite was run under strace and the files it opened were recorded, together
# with the paths its text names, and the sets were widened to the folder that holds
# them: a suite that read one file of scripts/quality/lint/ depends on that script
# and on the suites that exercise it, because the next change there may be the one
# it reads. A suite that WALKS a tree (`git ls-files`, `find`) depends on the whole
# tree by name, so its entry is `**`: the .editorconfig check reads every tracked
# file, which is why no path can be skipped as documentation only.
#
# PATTERN SYNTAX
#
#   *   matches within one path segment.
#   ?   matches one character within one path segment.
#   **  matches any number of segments, including none.
#   A bare path matches that path exactly.
#
# HOW TO EXTEND IT
#
# A new suite arrives without an entry, so it always runs until somebody writes
# one. When you add an entry, measure it the way this one was measured: run the
# suite under strace and record the files it opens.
#
# ---------------------------------------------------------------------------
